# 真实地理与来源

## 先核对地点

用官方景点/学校/城市网站核对地点名称、校区或区域，再用可下载地图确认几何。用户提供地点名并不等于提供了相机 GPS。默认标注区域中心或已核实的地标位置，并写 `approx. area` / `approx. campus area`；不要把内部投影所需的小数位包装成拍摄精度。

OSM 数据使用 WGS84 经纬度。高德/腾讯常见 GCJ-02、百度 BD-09，不能拿这些数值直接标到 WGS84 OSM 上。转换或重新核对时记录来源和不确定性。不同分校、校区必须区分；本次北京四中示例选择西城区主校区，其公开 OSM way 为 `412298305`，不是东校区。

## 数据选择

优先已有合法本地数据，其次下载开放矢量地图。OSM XML 能提供路网、建筑、水系、铁路、绿地、步道等。若地点缺数据，扩大到周边有识别性的地理范围或查合法开放数据；说明缺失，不手绘假细节。不要直接把商业地图截图抠白后作为默认制图数据。

城市/校园可从数公里周边开始；古镇重视主河道与山谷；海滨重视有足够范围的海岸曲线与内陆道路；区域/国家地图使用适合更大范围的投影与数据，不能直接套局部经纬度线性近似。

## 有界下载与缓存

小范围可使用 OSM API `https://api.openstreetmap.org/api/0.6/map?bbox=west,south,east,north`，或适合查询的 Overpass 实例。顺序为经度西、纬度南、经度东、纬度北。给下载留超时并缓存原始结果及时间，避免重复请求。

示例 PowerShell（将数值和输出路径替换为已核实目标，不在技能目录里缓存）：

```powershell
$mapUrl = 'https://api.openstreetmap.org/api/0.6/map?bbox=116.354,39.919,116.398,39.945'
Invoke-WebRequest -UseBasicParsing -Uri $mapUrl -OutFile './work/map.osm' -TimeoutSec 60
```

下载范围应比渲染范围留余量；先估计数据量。接口报告过多节点时拆成有限个相邻小块，按 `node/way/relation + id` 去重合并；不要高并发重试。临时网络失败最多少量重试，429/403 按服务提示停止或换合法数据来源。大区域用现成区域导出，别把编辑 API 当大规模下载服务。

检查 XML 确实是 `osm`，不是错误 HTML；节点坐标和 way 引用可解析。缺节点必须断开线段并报告，不能把缺口两端直线相连。水体 multipolygon 的 outer/inner 要分清；不能把分离岸段封口成三角形或填掉岛屿。默认脚本以真实岸线和已闭合 water way 的轻填色为主，不承诺完整的 GIS 多边形重建。

## 真实等高线

OSM 并不自带完整等高线。需要地形时使用有来源与许可的 DEM（例如公开高程栅格），采用地理软件或 marching squares 生成等高线，再在同一投影渲染透明图层。标明等高距与原始数据分辨率。不要把道路稀疏的问题用随机地形纹理掩盖。

本技能的默认脚本直接渲染 OSM 要素，**不自动下载 DEM 或生成等高线**。山地需求由调用 agent 按上述流程增加真实地形图层，并复用原图保护与验收约束；不可声称默认脚本已经完成未实现的步骤。

## 投影与核验

小范围中低纬地区可使用 `x ∝ (lon-west)·cos(midLat)`、`y ∝ north-lat` 保持近似地理比例。地图在照片中移动与等比例缩放不得改变内部相对关系。更大范围、极区或跨日期变更线需换合适的地图投影。

记录 source URL、下载日期、边界和坐标体系。核查标记与至少两个可辨认水系/道路的相对位置，字体不能掩盖错位。不要为贴合照片透视而扭曲地图，除非用户明确要求这种表现。

## 许可与署名

使用 OSM 时按发布形式保留 `© OpenStreetMap contributors`，并提供 https://www.openstreetmap.org/copyright。成品随附 manifest 要记录来源和许可；面向公开发布或印刷时检查署名可见且合规，不能把只存在于工作目录的元数据当成所有场景的署名。
